# Постпроцессоры и проверка G-code

G-code — семейство диалектов. Постпроцессор переводит задание (траектории, мощность, обороты) в команды конкретного контроллера. В SkyKerf_Studio траектории считаются один раз в нейтральном виде, а постпроцессор только «пишет» их нужными командами.

> **Ни один профиль не помечен «проверено».** Это не скромность: профиль получает этот статус только после испытания на реальном станке. Пока его нет, в интерфейсе, отчёте и заголовке файла стоит «не проверено». Помогите проекту — пришлите отчёт (Issues → «Проверка станка или постпроцессора»).

## Встроенные профили

| ID | Для чего | Ключевые решения |
|---|---|---|
| `grbl_laser` | GRBL 1.1 с включённым режимом лазера `$32=1` | `M4` (динамическая мощность), `S` в каждой строке `G1`, `G0` с выключенным лучом (только при `$32=1`), шкала `S` из профиля станка (`$30`), `M8/M9` для обдува |
| `generic_laser` | Любой лазерный контроллер, «только экспорт» | Самый консервативный код: `G21/G90/G94`, `M3 … M5` вокруг **каждого** контура, `S 0–1000`. Подходит для проверки в сторонних просмотрщиках |
| `grbl_cnc` | GRBL 1.1, фрезер | `G21/G90/G17/G94`, безопасная высота, `M3 S…` с ограничением `$30`, пауза `G4` для разгона шпинделя, смена фрезы через `M0` (у GRBL нет `M6`) |
| `generic_cnc` | Любой фрезерный контроллер, «только экспорт» | Консервативный код, комментарии в скобках `( … )`, `M30` в конце |

## Свой профиль

**Экспорт → «Свой профиль на основе этого…»** (режим «Про»). Можно изменить: название, расширение, точность, стиль комментариев, команду включения лазера (`M3`/`M4`), шкалу `S`, выключение луча на холостых, номера строк, возврат в ноль, конец программы, смену фрезы и паузу шпинделя, начальный и конечный блоки.

Ограничения ради безопасности (ТЗ, раздел 14):

- профиль — **набор правил, а не программа**: никакой код не выполняется;
- в начальном и конечном блоках разрешены только команды из списка профиля; остальные отклоняются при сохранении;
- подстановки только из белого списка: `{units}`, `{sMax}`, `{safeZ}`, `{machine}`, `{sheet}`, `{material}`; неизвестные остаются текстом;
- каждое сохранение создаёт **новую версию** (`v2`, `v3`…), прежняя сохраняется в архиве; копия профиля хранится в проекте, поэтому проект откроется и на другом компьютере;
- профили не загружаются из интернета.

## Проверка кода

После генерации и перед сохранением файл проверяется построчно:

| Проверка | Уровень |
|---|---|
| строка не разбирается; перемещение без `G0/G1` | ошибка |
| единицы в коде не совпадают с выбранными (`G20`/`G21`) | ошибка |
| выход за рабочее поле станка | ошибка |
| `S` больше максимума профиля или отрицательное | ошибка |
| рабочий ход без подачи `F` | ошибка |
| фрезер: резание при выключенном шпинделе, холостой ход `G0` ниже поверхности заготовки | ошибка |
| в конце нет `M5` | ошибка |
| холостые ходы при включённом `M3` с `S>0` (луч может гореть, если режим `$32=1` выключен) | предупреждение |
| подача выше максимальной для станка; глубина больше толщины листа; конец программы ниже безопасной высоты | предупреждение |
| команды вне списка профиля, системные команды (`$…`), `G91`; единицы не заданы явно; все рабочие ходы с нулевой мощностью | предупреждение |
| профиль не проверен на оборудовании | информация |

Экспорт с предупреждениями и даже с ошибками возможен — решение за вами, но кнопка прямо пишет «Сохранить с ошибками…». Проверка программы **не заменяет** холостой прогон.

## Экспорт

- Текущий лист или все листы (по файлу на лист).
- Единицы: мм (`G21`) или дюймы (`G20`, координаты пересчитываются).
- Расширение: `.gcode`, `.nc`, `.ngc`, `.tap` или своё.
- Кодировка: UTF-8 или ASCII (русские комментарии транслитерируются — для старых контроллеров).
- Метка времени в заголовке (можно выключить: тогда повторный экспорт того же проекта даёт **байт-в-байт одинаковый** файл).
- Отчёт `.report.txt`: проект, ревизия, контрольная сумма кода, станок, постпроцессор и его статус, материал, операции с параметрами и их источником, время, предупреждения.
- Производственный пакет: G-code + SVG + DXF + отчёт + `job.json` с настройками.

## Как испытать профиль на станке

1. Сделайте маленький тестовый проект: квадрат 20×20 мм на слое «Разметка» с минимальной мощностью (лазер) или гравировку глубиной 0,2 мм (фрезер).
2. Экспортируйте выбранным профилем с отчётом.
3. **Холостой прогон**: лазер — мощность 0 или поднятая головка; фрезер — фреза выше заготовки (сместите ноль Z вверх).
4. Проверьте: направление осей, размер, отсутствие луча на холостых, включение/выключение шпинделя, возврат в конце.
5. Реальный проход на обрезке материала.
6. Пришлите отчёт через Issues: модель станка, прошивку (`$I`), id и версию профиля, что работало и что нет. После нескольких подтверждений профиль получит статус «проверено» в следующей версии.
