# Переименование: Kerf Studio → SkyKerf_Studio

Версия 0.3.0 выходит под именем **SkyKerf_Studio**. Этот документ описывает, что переименовано в коде, что намеренно оставлено ради совместимости и как переименовать репозиторий на GitHub, не потеряв историю, задачи, релизы и ссылки.

## 1. Что уже переименовано в коде

| Где | Было | Стало |
|---|---|---|
| Название окна, «О программе», заголовок G-code и отчётов | Kerf Studio | SkyKerf_Studio |
| `package.json` → `name` / `productName` | `kerf-studio` / `Kerf Studio` | `skykerf-studio` / `SkyKerf_Studio` |
| Имена установщиков | `KerfStudio-Setup-…exe`, `KerfStudio-…AppImage` | `SkyKerf_Studio-Setup-…exe`, `SkyKerf_Studio-…AppImage`, `SkyKerf_Studio-…deb` |
| Артефакты GitHub Actions | `KerfStudio-Windows/Linux` | `SkyKerf_Studio-Windows/Linux` |
| API настольной версии в странице | `window.kerfDesktop`, каналы `kerf:*` | `window.skykerfDesktop`, каналы `skykerf:*` |
| Ключи настроек в браузере | `kerf.*` | `skykerf.*` |
| Папка настроек Electron | `…/Kerf Studio` | `…/SkyKerf_Studio` |
| Ссылки, бейджи, homepage | `OWNER/kerf-studio` | `skysyndicatecorner/SkyKerf-Studio` |

Слово **kerf** в коде и интерфейсе — это технический термин (ширина реза), оно не переименовывалось: `kerfPaths`, «Тест керфа», поле `kerf` в материалах и т. д.

## 2. Что оставлено специально

- **Расширение проектов `.kerf`.** Старые проекты открываются как раньше, файловая ассоциация в Windows/Linux сохраняется. Формат внутри — новый (версия 3), но старые версии 1 и 2 читаются и преобразуются.
- **`appId` = `org.kerfstudio.app`.** От него зависят ключ установщика Windows и группировка на панели задач. Если оставить его прежним, установщик 0.3 заменит установленную 0.2, а не поставит вторую копию рядом. Ожидаемое поведение NSIS-установщика electron-builder при совпадающем `appId` — удалить старую версию программы перед установкой новой (папка настроек при этом не удаляется). Проверьте на чистой системе перед массовой раздачей.
- **Старые ключи `kerf.*` и старая папка настроек** не удаляются: при первом запуске их содержимое **копируется**. Если что-то пошло не так, можно вернуться к 0.2 — её данные целы.

## 3. Миграция данных пользователя

При первом запуске 0.3:

1. **Настольная версия:** если существует папка настроек `Kerf Studio` (Windows: `%APPDATA%\Kerf Studio`, Linux: `~/.config/Kerf Studio`), из неё копируются `Local Storage`, `IndexedDB` и `autosave` в новую папку `SkyKerf_Studio`. Создаётся файл `migrated-from-kerf-studio.json` с отметкой, что и откуда скопировано. Старая папка не трогается.
2. **Страница/браузер:** ключи `kerf.project`, `kerf.lang`, `kerf.mode`, `kerf.tab`, `kerf.theme` копируются в `skykerf.*`, если новых ещё нет. Старые ключи остаются.
3. **Автосохранённый проект** открывается и преобразуется в формат 3. Слои старого проекта получают режим «параметры вручную» с прежними значениями, чтобы результат резки не изменился сам собой.
4. **При сохранении поверх старого файла** рядом создаётся резервная копия `имя.backup.kerf`.

## 4. Переименование репозитория на GitHub

> Делайте это сами, из своего аккаунта. Не создавайте новый пустой репозиторий с новым именем — потеряются звёзды, задачи, релизы и перенаправления.

### 4.1. Проверьте фактический адрес и владельца

Ожидаемый старый адрес — `https://github.com/skysyndicatecorner/Kerf-Studio`, но проверьте:

1. Откройте `https://github.com/skysyndicatecorner?tab=repositories` и найдите репозиторий проекта.
2. Убедитесь, что **владелец** — `skysyndicatecorner` и у вас есть права **Admin** (вкладка **Settings** видна).
3. Запишите точное старое имя (регистр, дефисы).

### 4.2. Переименуйте

1. Репозиторий → **Settings → General**.
2. **Repository name** → `SkyKerf-Studio` → **Rename**.
3. GitHub автоматически перенаправляет старые веб-ссылки и git-адреса на новое имя. Перенаправление перестанет работать, только если кто-то создаст новый репозиторий со старым именем у того же владельца — не делайте этого.

### 4.3. Обновите локальные копии

Только после того как новый адрес открывается в браузере:

```bash
git remote -v                       # посмотрите текущий адрес origin
git remote set-url origin https://github.com/skysyndicatecorner/SkyKerf-Studio.git
git remote -v                       # проверьте
git fetch                           # убедитесь, что доступ есть
```

Токены и пароли в адрес remote не вписывайте — используйте вход через браузер или менеджер учётных данных.

### 4.4. Проверьте после переименования

- [ ] Вкладка **Actions**: запуски **Tests** и **Build desktop** видны; ручной запуск работает.
- [ ] Бейджи в README показывают статус (адреса уже указывают на `skysyndicatecorner/SkyKerf-Studio`).
- [ ] **Releases**: старые релизы на месте; новый релиз `v0.3.0` собирается с файлами `SkyKerf_Studio-*`.
- [ ] **Settings → Secrets** (если были) сохранились — секреты не зависят от имени репозитория.
- [ ] **Description / Website / Topics** на главной странице репозитория обновлены вручную (их нет в файлах).
- [ ] GitHub Pages (если используются) — адрес сайта изменится на новое имя.
- [ ] Внешние ссылки (форумы, соцсети) продолжат работать через перенаправление, но лучше обновить.

## 5. Что сделать пользователям

Ничего особенного: установить 0.3 поверх 0.2 (или распаковать portable-версию). Проекты и настройки подхватятся. Если что-то не перенеслось — откройте старый `.kerf` через «Файл → Открыть».
