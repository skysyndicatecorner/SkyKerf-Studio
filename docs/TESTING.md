# Тестирование

## Автотесты

```bash
npm test          # node --test "tests/*.test.js", ~5 секунд, без браузера и Electron
```

Тесты загружают модули программы в изолированный контекст Node (`tests/harness.js`) и проверяют:

| Файл | Что проверяет |
|---|---|
| `geometry.test.js` | смещения, булевы операции, компенсацию реза (снаружи/внутри), поиск дубликатов, объединение сегментов, самопересечения |
| `nesting.test.js` | режимы «один лист / несколько / текущий»; причины неразмещения; поля, запретные зоны, препятствия, отсутствие пересечений; материал и толщину; детерминизм; вложение в отверстие |
| `post.test.js` | для каждого встроенного постпроцессора код проходит свою проверку; повторный экспорт байт-в-байт; дюймы; ASCII; проверка ловит опасный код; число контуров в предпросмотре совпадает с планом; белый список подстановок |
| `migration.test.js` | открытие реальных проектов Kerf Studio v1 и v2 (`tests/fixtures`), перенос фото в assets, понятные ошибки для повреждённых/чужих/новых файлов, нормализация неполных файлов, копирование старых настроек, история с названиями |
| `materials.test.js` | все встроенные профили «не проверено»; источник параметров; явное сообщение о неподдерживаемой операции; параметры под станок; безопасный импорт библиотеки |
| `brand.test.js` | нет остатков старого названия вне заметок о переходе; метаданные пакета; версия совпадает; страница не грузит ничего из сети |

Те же тесты запускаются в GitHub Actions при каждом push (`Tests`) и перед каждой сборкой (`Build desktop`).

## Ручная приёмка

Сценарии из ТЗ (раздел 15). Отмечайте ✓ / ✗ и версию.

### A. Новичок, лазер, простой режим

1. Новый проект: диодный лазер, фанера 3 мм, лист 300×200.
2. Мастер «Строение» → «Чайный домик» → «Добавить и разложить…» → «Несколько листов» → «Применить».
3. Удалить лишний пустой лист кнопкой корзины на панели листов (простой режим!).
4. Ctrl+Z на **русской раскладке** — лист вернулся.
5. «Подготовить» → вкладка G-code: проверка кода пройдена, время показано.
6. «Экспорт» → GRBL лазер → «Сохранить…»: файл `.gcode` и отчёт `.txt`.
7. Закрыть программу из диспетчера задач (аварийно) → запустить: предложено восстановление или проект на месте.

### B. Опытный пользователь, фрезер, режим «Про»

1. Открыть проект Kerf Studio 0.2 (`tests/fixtures/kerf-studio-v2.kerf`): сообщение о преобразовании, 2 листа, фото на месте.
2. Сменить станок на фрезер 6060: предупреждение о замене материалов листов.
3. Импорт PNG → «3D-рельеф» → «Добавить на лист» → «Только текущий лист».
4. CAM: порядок «Вручную», переставить операции; слой резки — «Вручную», изменить подачу; «Режимы из материала» — значения вернулись.
5. Проверка геометрии: сдвинуть деталь за край листа — появилась ошибка, клик по ней выделяет деталь.
6. Экспорт «Все листы» в дюймах, `.nc`, ASCII, производственный пакет → папка с G-code, SVG, DXF, отчётом и `job.json`.
7. Станок → USB/Serial → подключение: статус, «Считать сведения о контроллере» → черновой профиль с полями «считано / подтвердите». Задание **не** стартует само.

### C. Проверки качества

- 2000+ объектов (массив 45×45): список объектов прокручивается плавно, поиск работает.
- Перетаскивание SVG, DXF, PNG, TIFF, STL, `.nc`, `.kerf` в окно.
- Текст системным шрифтом → сохранить → открыть на машине без шрифта: предупреждение, контуры на месте.
- Переключение RU/EN на каждом диалоге; светлая/тёмная тема.
